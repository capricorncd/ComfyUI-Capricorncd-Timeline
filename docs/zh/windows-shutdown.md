# 工作流完成后强制关机 (Windows)

此节点由 `ComfyUI-Capricorncd-Timeline` 提供，位于 `Capricorncd` 分类。

重启 ComfyUI，搜索 `CAP_WindowsShutdown` 或「工作流完成后强制关机」，添加到工作流。

- `trigger`：必需连线，接受任意类型的上游输出。for 循环建议连接循环结束节点的输出；节点只登记请求，不会在中间迭代直接关机。
- `enabled`：默认 **true**。关闭后本次节点执行不登记请求。
- `condition`：默认 `always`，执行到节点就登记关机。其他条件比较 `trigger` 和 `match_value`，不匹配则跳过本次登记。
- `match_value`：比较目标，`always` 模式不使用。
- `delay_seconds`：工作流成功完成后的倒计时，默认 60 秒，0 为立即关机。
- 等待当前工作流所有执行分支完成并写入执行历史，且**整个队列为空**才开始倒计时。一次排入几十个任务时，不会在第一个任务完成后关机；后续任务无需都包含此节点。缓存命中也会重新登记请求。
- 失败或取消会清除已登记的关机请求，后续任务若再次执行开启的关机节点，可以重新登记。多个请求采用最长倒计时，并只触发一次关机。
- 关闭、删除节点不会撤销先前任务已经登记的请求；可重启 ComfyUI 清除尚未触发的请求。请在倒计时开始前完成任务入队；倒计时开始后新加任务不会自动取消系统关机。
- 使用 Windows `shutdown.exe /s /f /t 秒数`，会强制关闭应用，未保存内容会丢失。倒计时开始后，可按 Win+R 输入 `shutdown /a` 取消；修改节点不会取消已经开始的系统倒计时。

节点在执行时登记请求，通过当前队列实例的 `task_done` 适配器在成功结束后触发。不修改 ComfyUI 核心，不增加依赖或网络请求。关机命令失败会记录到 ComfyUI 控制台。

## 触发条件

| condition | 含义 | 匹配示例（trigger / match_value） |
|---|---|---|
| `always`（默认） | 执行到节点就登记，不检查输入值 | 任意输入 |
| `number_equals` | 数字等于 | 数字 `20` / `20` |
| `string_equals` | 字符串完全相等 | `done` / `done` |
| `string_starts_with` | 字符串以目标开头 | `done_001` / `done_` |
| `string_ends_with` | 字符串以目标结尾 | `001_done` / `_done` |
| `string_includes` | 字符串包含目标 | `task_done_001` / `done` |

数字条件接受数值输入，数字字符串不自动转换；`20` 和 `20.0` 相等，布尔值不作为数字。数字目标无效时报错。字符串条件只接受字符串，区分大小写并保留空格；空目标遵循普通字符串匹配规则（开头、结尾、包含均匹配任意字符串）。

例如循环计数到 20 时关机：把计数输出接到 `trigger`，选择 `number_equals`，`match_value` 填 `20`。按循环节点实际输出的计数设置目标（有些从 0 开始）。匹配只登记一次请求，仍等待工作流及队列完成。不匹配不会撤销此前已经登记的请求。
