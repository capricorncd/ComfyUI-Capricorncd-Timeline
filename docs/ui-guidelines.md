# UI 设计与验收规范

适用于时间轴编辑器的页面、弹窗、浮窗、卡片和表单。新增 UI 与修改中的 UI 必须遵循；不为统一样式顺带重写无关页面。

本文规定信息组织和视觉行为；[组件文档](ui-components.md)规定组件接口。开发前先查看同类现有界面，复用组件和交互。用户在当前任务中明确提出的要求优先，并在形成通用约定时更新本文。

## 实现原则：优先 Web Component

- 先查找 `js/components/` 和组件文档，优先复用已有组件，再扩展通用能力，最后才新增组件。
- 将重复的 UI 与完整交互一起封装，例如复制图标及成功反馈、提示词展示、媒体预览、字段布局；不能只复用外壳，仍在各页面重复状态和事件逻辑。
- 组件负责内部布局、主题样式、键盘操作、可访问性和反馈；页面负责业务数据、加载保存及外部布局。
- 使用属性、方法、slot、自定义事件作为公开接口，禁止业务页面依赖组件内部 DOM。Shadow DOM 按现有组件模式使用，表单需要 light DOM 时保留其原生语义。
- 共享样式和行为只维护一份。提取后删除本次涉及的旧实现，并在组件文档记录接口与验证方式。
- 一次性静态布局不必包装为空壳组件；不预建无实际调用的配置，不为组件化引入新框架或批量改造无关页面。

## 1. 信息必须有主次

- 第一层是对象名称，如工程名、Clip 名；第二层是主要内容，如提示词和素材；第三层是辅助信息，如时间、数量、文件名。
- 弹窗的功能名称可用较小的辅助文字，工程名作为主标题。不要把所有内容合成一行同等强调的标题。
- Clip 标题行放序号、名称、时间范围和时长。时间紧凑展示，默认换算为秒；不要把“开始时间”“时长”各做成占两行的大字段。
- 标签、时间、文件名使用次级文字颜色与较小字号；正文保持正常字重；只有标题和关键数值需要强调。
- 避免每个字段都加粗、所有块都有醒目边框、同一屏出现多个竞争的主操作。
- 原始 JSON、调试字段和内部标识不能成为主要内容；确有查看价值时放入次级折叠区。

## 2. 留白与对齐

以下为浏览型弹窗的默认布局值，不是按钮内部样式，也不要求给所有页面添加同名 CSS 变量。

| 部位 | 常规窗口 | 窄屏 |
| --- | --- | --- |
| 内容区左右留白 | 28px | 18px |
| 内容区上下留白 | 20px | 16px |
| 轨道导航左右留白 | 与内容区一致 | 与内容区一致 |
| 卡片内容内边距 | 16px | 可缩至 12px |
| 卡片之间 | 16px | 12–16px |
| 素材与正文间距 | 18px | 改为上下排列 |

- 标题、导航、卡片和表单应有明确的对齐线。内容不能贴着弹窗边缘。
- 相关字段靠近，独立分组拉开距离；不要用大量空行代替分组。
- 布局必须适应弹窗手动缩放。长名称和长路径应换行或提供完整内容提示，不能把操作挤出视口。
- 常规窗口采用分栏时，窄屏改为单栏；不得产生整个弹窗的横向滚动。轨道导航可以独立横向滚动。

## 3. 字体与主题

- 跟随编辑器的 `--cat-font-size` 字号设置，页面文字使用相对比例；默认字号下，主标题约 16px、卡片标题约 14px、正文约 13px、辅助文字约 11–12px。
- 正文行高约 1.6–1.75；时间和数值可使用等宽数字，提示词默认沿用正文的字体。
- 使用现有 `--cat-bg`、`--cat-surface`、`--cat-raised`、`--cat-text`、`--cat-muted`、`--cat-border-soft`、`--cat-accent` 等主题变量。
- 不为业务页面硬编码另一套深色/浅色配色。强调色用于选中、关键状态等有限场景。
- 卡片用柔和边框或背景区分，不把每个字段都画成独立重边框卡片。

## 4. 按钮与图标

- 使用 `cap-button`、`cap-dropdown-button`、`cap-tab-button` 等共享组件。页面只负责外部布局，不覆盖按钮内部颜色、边框、间距及状态样式。
- **复制按钮只显示图标，不显示“复制”文字。** 使用 `cap_icons.js` 的 `copy` 图标，沿用现有小号方形按钮：`shape="square"`、`size="small"`、12px 图标。
- 复制按钮位于对应内容标题右侧；复制完整原文，不能复制裁剪后的摘要或格式化展示值。
- 复制成功使用 `check` 图标与组件 `success` 状态，约 1200ms 后恢复；重复点击重置反馈时间。失败显示明确反馈，不能假装成功。
- 图标按钮必须有本地化 `title` 和 `aria-label`；反馈状态变化时同步更新名称。
- 加载其他工程、保存、导出等需要明确含义的全局操作保留文字。不要把所有按钮都改为图标。
- 复用公共 SVG 图标，不使用 Unicode 字符或 emoji 替代已有图标。

## 5. 弹窗与滚动

- 使用 `cap-dialog`，复用其标题栏、关闭、拖动、缩放、阴影和视口限制。
- header 显示名称，body 显示内容，footer 放全局操作；固定头尾，内容区滚动。
- **只读提示词完整展开，不能设置独立滚动、固定高度、行数截断或默认折叠。** 长提示词由弹窗内容区统一滚动；复制按钮仍复制完整内容。
- 上述规则针对提示词阅读区；不改变可编辑输入框、已有分镜摘要卡片、媒体列表或原始信息折叠区的用途。
- 多轨道浏览时保持导航易于访问，可在内容滚动区顶部吸附。不要让用户滚动很久才能切换轨道。
- 选择模态弹窗还是浮窗取决于是否需要同时操作底层时间轴，遵循组件文档；不能为了布局方便阻断原有交互。
- 关闭弹窗或切换内容时停止音视频播放。不要自动播放带声音的视频。

## 6. Clip 与素材浏览

- 有素材时，宽窗口默认左侧素材、右侧提示词，素材列约占 27%，正文占剩余空间。没有素材时正文占满宽度，不保留空列。
- 图片和视频预览保持比例、完整显示，默认 `object-fit: contain`，不能为填满容器裁掉参考内容。
- 视频提供播放控制，素材文件名作为弱化的辅助信息。素材缺失有明确占位说明。
- Clip 名和提示词是主要内容；媒体引用、技术信息不能把主要内容挤到很后面。
- 同名轨道必须独立显示和切换，不能用名称去重或作为唯一标识。
- 参考工程中导演轨道优先、默认选中，其他轨道保留相对顺序，全局设置放在最后。
- 全局设置先展示宽度、高度、帧率等紧凑指标，再展示全局提示词与其他设置，避免所有值平铺为同样大小的长段落。

## 7. 状态与数据行为

- 空内容、加载中、取消、失败、成功和素材缺失都必须有合理状态。状态消息使用共享组件。
- 已加载的参考工程再次打开时直接显示；重新选择取消或失败时保留原内容。
- 只读浏览不能修改当前工程。浏览、切换 Tab 和复制不写撤销历史。
- 外部工程名、提示词、文件名用纯文本呈现，不作为 HTML 注入。
- Tab 保留键盘导航与选中语义；操作使用本地化文案。新增 UI 延续项目的中文、英文、日文支持。

## 8. 交付前检查

修改 UI 时按实际影响检查，不为纯间距调整新建实现镜像测试。

- 检查标题、正文、辅助信息能否一眼区分，左右是否留白、对齐。
- 检查长提示词完整展示且无内部滚动，复制为原文，复制按钮无可见文字。
- 检查长名称、多轨道、同名轨道、无素材、图片与视频等相关场景。
- 检查浅色/深色、编辑器字号变化、窄屏和弹窗缩放，不只检查默认尺寸。
- 有行为变化时运行相关测试；有布局变化时尽可能在浏览器查看实际效果。没有做视觉检查时不能声称已完成视觉验证。
- 复用同类界面的成熟做法后再交付，不把按钮形态、留白、文字层级等常规细节留给用户逐项纠正。
